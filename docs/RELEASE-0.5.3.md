# Salcara Hub 0.5.3

本版配套 **Salcara Android 1.8.3** 和 **Salcara Desktop 1.6.5**，提供管理员账号、用户与设备管理、来源授权及后台更新检测。首页和公开状态页从同一嵌入清单显示这组客户端版本。

- 管理后台支持账号和密码登录、用户档案、登记码归属、设备筛选、禁用/启用与每个用户的独立来源名单。被禁用手机保留配对，重新启用后可恢复连接。
- 分类控制本站 API、外站 API、反代账号和受支持的官方账号；电脑端使用选定站点和设备凭据获取有效策略，拒绝过期授权或不支持新策略的客户端。
- 增加多入口、代理池与线路观察、持久消息恢复、协作管理、审计、监控接口和完整数据目录备份恢复。
- 新 launcher 默认每 6 小时检测签名更新；管理页显示新版，安装仍需管理员确认。网页更新只替换 Hub 子程序，launcher、基础镜像和 Compose 需通过完整镜像升级。
- 保留既有 Ed25519 发布身份，按同一源码构建双架构镜像及 Hub/launcher；不覆盖历史版本资产。

## 升级

先升级到配套 Desktop，再启用或保存 v2 分类/用户来源授权。仅展示配套版本不会自动提高最低强制版本，本次不提高该门槛。

备份原部署配置及**完整数据卷**，保留原项目名、卷名和 HTTPS 地址，将固定镜像切到 `ghcr.io/dkdjndbfj-wq/salcara-hub-standalone:0.5.3`。不要重新初始化，不执行 `down -v`。旧 0.4.0 的认证迁移仍须按 [部署说明](STANDALONE-DOCKER.zh.md) 完成。

初始管理员账号为 `admin`，密码沿用原管理密钥；设置自定义账号后需填写该账号。新增 `managed-users.json` 及登记码用户归属。已有设备默认未分配并沿用全站策略；将已绑定电脑关联或移交用户会撤销原手机凭据，需要重新配对。启用新用户策略后，不支持把直接降级旧二进制当作保留权限语义的回滚。

## 验证范围

发布构建执行 Linux Go 测试、vet、race、前端/部署回归、OCI 归档及签名资产校验，并对 amd64 容器做非 root、只读运行检查。arm64 为交叉构建及产物校验，不宣称已经实机运行。

Bot 的整组手机凭据不支持单台电脑迁移用户。签名来源模式需另行配置来源发行服务；代理池是可选能力，没有实测提速承诺。本次 GitHub 交付不包括用户 VPS 部署、实体手机全链路/FCM 验收或 iOS 签名发行。
