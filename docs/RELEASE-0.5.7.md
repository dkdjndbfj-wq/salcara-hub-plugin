# Salcara Hub 0.5.7

本轮配套发布目标为 Salcara Android **1.8.7（versionCode 28）** 和 Salcara Desktop / Bridge **1.6.10**。Hub 0.5.7 是配套版本显示更新，不包含新的 Hub 业务或协议修复。

## 本版范围

- 公开首页和状态页继续共用 `internal/standalone/web/client-versions.json`，将配套客户端版本同步为本轮目标；不在页面中另写一套版本号，不增加远程版本查询。
- Hub 构建、正式安装器及其验证使用 0.5.7 目标。保留 0.5.6 已有的任务恢复、待发撤回、Bot 清理和登记恢复行为，历史修复范围见 [0.5.6 版本说明](RELEASE-0.5.6.md)。
- 桌面导航布局、时间不一致诊断，以及手机时间错误分类和已保存身份锚的处理，属于对应客户端本轮修复范围，具体交付及验收以各客户端版本说明和发布记录为准。仅升级 Hub 不会替用户更新电脑或手机软件，也不会替操作系统校时。

## 身份与兼容边界

沿用原 Ed25519 发布身份 **`salcara-local-20260930`**；不修改 Hub 实例身份、签名密钥、设备绑定、配置、数据格式或依赖，不提高最低准入版本，不新增强制更新策略。

时间不一致不表示 Hub 身份需要重置。保留客户端已保存的身份锚与配对凭据，不清空 pin、不重新初始化 Hub、不降低签名、身份、nonce 或入口成员检查来绕过错误。

## 发布与验收状态

本说明在本轮正式公开和线上部署前编写。流程先完成同一冻结源码的正式构建、独立原产物和 OCI 验证、原发布密钥签名，再准备 GitHub Release 草稿；三端统一确认前不公开新版本。草稿、镜像构建或文档本身均不是正式公开或线上部署完成的证明，实际状态以本轮发布记录为准。

正式公开后须逐个下载实际公开文件，核对大小、SHA256 和原公钥签名；通过后才单独更新 `main/updates/standalone-account.json`。保留旧协议更新源、原公钥和全部旧版本资产，不覆盖已有版本。完整步骤见 [发布维护流程](STANDALONE-RELEASE.zh.md)。

配套版本清单嵌入 Hub 二进制；发布手机、桌面、Hub 源码、镜像或更新清单都不会自动改变已运行服务器的页面。本轮不安排服务器部署，已运行页面仍以现场版本为准。以后升级须另行获授权，并核对实际 `/healthz`、首页和 `/salcara-hub/status` 版本；仍保留完整数据与原部署配置，不重新 `-init`，不删除数据卷或用旧备份恢复已撤销的权限。见 [Docker 部署说明](STANDALONE-DOCKER.zh.md)。

本说明不把旧版本测试当作本版验证，也不宣称亮色／暗色／窄屏视觉、arm64 实机、真机端到端或真实 Agent 任务验收已通过。具体已完成项和未完成项须由本轮实际证据分别记录。
