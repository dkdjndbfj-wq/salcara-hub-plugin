# Hub 续接修复与冻结验收（2026-10-14）

接续旧对话中断前的 Hub / 发布范围。账号管理、手机搜索/仅图片发送、桌面启动步骤由协作对话负责；本轮没有修改它们的源码，也没有执行发布、签名上传或生产部署。保留工作树原有未提交修改。

## 本轮新增修复

### 指令实际入队前的状态复核

`internal/hub/admin.go` 的原流程在来源检查之前读取设备和连接。来源检查等待期间，取消请求、撤销配对、更换连接或关闭 Hub 后，原请求仍可能把指令放进旧连接队列。

新增 `command_dispatch_admission_test.go` 先复现：取消、撤配对、换连接、Hub shutdown 四个场景均把旧指令放进队列；撤配对/换连接还会等到 504。已关闭连接由于 Go select 可同时选中可写通道，其错误行为具有竞争性。

修复在来源检查之后、实际非阻塞入队之前，持有 `h.mu` 再检查取消、Hub 关闭、原设备身份/配对、原连接、备用连接及 TTL；检查与入队之间不释放这把锁。闭合通道先单独检查，避免已经关闭但尚有队列空间时随机入队。来源策略锁只保持到入队，不跨越等待回复。

八个新场景包括上述五类失效、备用连接过期/更换，以及已经持久化受理的指令在手机取消后仍继续执行且同编号重试只取原回执。此次修复没有改变持久化受理后的断线语义。取消恰好发生在最终检查之后仍属于提交边界竞争，不能宣称能撤回已入队指令。

### 启动器异常退出后的接管边界

`internal/launcher/process_linux.go`、`run_linux.go` 让子 Hub 继承启动器的同一个卷锁。启动器遭 SIGKILL 后，旧 Hub 完成退出之前，新启动器不能提前接管；正常升级/回退仍由父进程持续持锁。

默认 Linux 进程测试已先红后绿，并经另一子代理只读复核。Hub 自身原有独立数据锁通常能拒绝第二写入者，因此本次不能描述成已复现真实用户数据双写。具体证据见 [更新恢复专项](HUB-UPDATE-RECOVERY-20261014.md)。

## 新增实际链路证据

- 真实 HTTP/1.1 loopback TCP：App 慢写、native deadline、队列溢出期间预算保留、429 重试契约、另一用户持续收流、34 条事件按游标重放后继续在线；App SSE / Bridge SSE / 长轮询分别覆盖 FIN、RST 断连及重新准入。生产 deadline 仍为 30 秒，测试 socket 缩短为 2 秒以验证实际超时。见 [TCP 专项](HUB-TCP-RECOVERY-20261014.md)。
- 实际 Hub 二进制：初始化、HTTP 管理更新经 Unix 控制代理切换程序、重启选择已确认缓存、下载中途 EOF 保持旧进程、健康版本不符后停止候选并回退。管理凭据、合成手机 token、项目、封禁和资源/清理设置保留，旧管理 cookie 失效。
- 两份升级实验程序来自同源码，仅编译版本标识为 0.5.2 / 0.5.3；feed/签名为隔离合成输入。它验证实际程序生命周期，不是历史已发布版本的数据迁移或正式 HTTPS 更新验收。

## 剩余放行条件

上述两处可复现缺陷已修复，本轮 Hub 本地回归完成。全产品仍不能直接按“全功能商业正式版”放行：

1. 原生 Codex API/账号执行来源无法可靠证明，生产控制门禁保持；Claude Desktop Code 的托管模式不等于接管完整原生桌面。跨任务消息来源和 Hermes 等未完成能力仍沿用总验收记录，不能被本轮 Hub 结果覆盖。
2. 协作对话的账号、手机与启动步骤修改需各自冻结后合并验收；旧手机 1,958 项结果不代表本日后续修改。
3. Android 原生构建及真实手机通知、带图发送、弱网切站、休眠唤醒仍需实机；此次 loopback TCP 不包含 TLS/HTTP2、反向代理或移动网络。
4. 历史真实发布产物升级、正式双架构 OCI/SBOM、ARM 运行、冻结提交 CI、正式签名和 HTTPS 下载链路仍需独立证据。
5. 目标服务器长时负载、磁盘压力及 CPU/RSS 容量尚未完成。共享预算和本地并发隔离通过不构成付费用户人数保证。

此前的 [发布产物一致性审计](RELEASE-CONTRACT-AUDIT-20261014.md) 及 Bridge 总验收记录仍有效，本记录仅补充新修复和新实测范围。
