# 0.5.0 Docker Hub 变更与复核记录

## 范围

本次基于 `f477f11c247e5eda7b35669976ebbc748a7b22f5` 整理为完整的 Salcara Hub 项目。只改 Docker Hub；没有修改手机、桌面 UI / 动效，没有发布个人版，也没有部署到用户服务器。文档示例域名仅为占位符。

## 项目整理

- 唯一源码结构为根目录 `cmd/`、`internal/`、`tools/`，唯一 Go 模块为 `salcara/hub`，仅使用标准库。
- 删除旧插件入口、SDK、打包器、页面、宿主适配补丁及不再使用的构建流程、依赖许可；保留项目 LGPLv3、引用的 GPLv3 与 Go 许可。
- Docker、CI、测试、发布工具和文档统一使用新路径；没有第二套内核或需要拼接的补丁。旧代码可从 Git 历史恢复。
- README 介绍独立产品、配套 App、部署、使用和维护。已有下载地址、产品 ID、发布者公钥、设备协议及数据 schema 保持兼容，不擅自重命名仓库破坏更新地址。
- 源码迁移只机械调整 import，保留配对与转发行为；不可达的旧模型 Key 鉴权内部代码暂未进行协议改造。独立入口始终关闭该路径。

## 管理密钥链路

- 首次 `-init` 生成每站独立的 256 位随机管理密钥，存为 `/data/admin-initial-login.txt` 单行私有文件；日志不输出密钥。`admin-account.json` 只存盐和 PBKDF2-SHA256（600000 次）派生哈希。
- 管理页没有用户名，不再读取 URL、localStorage、sessionStorage 或管理 Bearer token。登录后使用 HttpOnly、SameSite Strict Cookie；生产 HTTPS 另设 Secure。
- 管理修改请求验证精确 Origin、JSON Content-Type、CSRF。登录尝试、密钥派生并发及管理员会话数量有界。
- 现有控制台增加「更换密钥」入口。验证旧密钥，确认新密钥；成功撤销所有管理员会话，删除卷中的初始明文文件，重新登录。主机上已导出的失效副本需用户自行删除。
- 忘记密钥：先停止 Hub，用同卷执行 `-reset-admin-key`，再私下导出新的初始密钥文件、启动 Hub。恢复操作要求持独占卷锁；不接受秘密命令参数，不清除设备绑定、封禁或资源模式。
- 重置先提交私有恢复文件，再提交哈希；第二步失败尝试恢复原文件。两次提交间断电需要重新执行重置，始终拒绝未认证管理，不声称两文件具有跨文件原子事务。

## 部署、迁移与更新

- 新增首次部署脚本：校验 Linux、本机 Docker、专用新目录、已有容器 / 数据卷 / 端口和正式 Release；失败不清理旧服务，不安装 Docker，不修改反代，不伪报公网部署成功。
- 完成后给出管理 URL、管理员 iframe URL、普通用户说明 URL、私有密钥文件路径及安全读取命令；详细区分用户手工部署和 Agent 代部署的交付要求。
- 0.4.0 迁移必须先停机备份并初始化新认证文件，不能继续使用旧管理令牌。
- 新认证版本使用独立签名更新源 `updates/standalone-account.json`；旧 `updates/standalone.json` 保留原版本，避免缺认证文件的跨版本网页升级。
- 网页更新仍只更新经签名验证的 Hub 子程序，不管理 Docker socket、不更新 Sub2API。基础镜像 / launcher 更新通过 Docker；进程重启需重新登录。
- 新增 / 更新 secret 忽略规则，公开仓库不包含真实部署配置、服务器凭据、管理密钥或发布私钥。

## 明确边界

普通用户扫码配对不需要管理密钥；管理密钥仅用于 Hub 管理员。管理入口不能无鉴权公开。Hub 当前并非端到端加密，运行方能够读取转发内容。网页更新缓存目前不自动清理；管理员仍需监控卷空间并备份。
