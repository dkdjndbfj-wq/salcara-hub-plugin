# 管理员登录、用户与设备管理

本文对应当前开发源码。历史 `standalone-v0.5.2` 镜像未包含本页新增功能；源码更新不代表正式镜像或安装包已发布。

两个入口使用不同链接：管理员访问 `/salcara-hub/admin/`，未登录显示登录页，登录成功后在同一入口进入后台；普通用户访问 `/salcara-hub/status`，无需管理员账号。公开状态页只展示服务可用性、浏览器检测耗时和全站来源类别状态，不提供设备清单、用户资料或管理操作。后台的「用户状态页」链接会另开页面。

## 管理员登录

访问 `https://你的域名/salcara-hub/admin/`，填写管理员账号和密码。首次进入或从旧版升级，账号使用 `admin`，密码使用原来的管理密钥。

在「系统 → 管理员账号与密码」中可同时更改账号和密码。账号支持 3–64 位字母、数字、点、下划线和连字符；密码至少 16 个字符。设置账号后必须填写匹配的账号，不能继续省略账号登录。更改后所有管理会话退出，需要重新登录。

管理会话沿用受保护的 Cookie、CSRF 检查和登录限速；浏览器不保存管理员密码。运维／只读协作者继续使用各自的管理密钥，账号可填写协作者名称或留空，不能用主管理员账号代替。

忘记账号或密码时，按 [部署教程的恢复流程](STANDALONE-DOCKER.zh.md) 停服并执行离线 `-reset-admin-key`。恢复会生成新管理密钥，并将主管理员账号恢复为 `admin`；用户和设备数据保留。不要重复运行 `-init` 或删除数据卷。

## 用户怎样接入

1. 管理员在「用户」添加档案，填写姓名／称呼及可选备注。
2. 在「设备 → 新电脑登记」选择该用户，生成一次性登记码，通过可信渠道交给电脑使用者。
3. 电脑填写 Hub 地址和登记码，首次登记后自动归到该用户名下。登记码 24 小时有效，只能登记一台电脑，原文仅在生成时显示。
4. 手机按原流程填写 Hub 地址、扫码配对。用户不需要另建登录账号，也不需要选择代理节点。

电脑登记成功、手机配对完成，且用户和设备未被禁用后，即可使用管理员允许的远程能力，不需要逐次审批。模型来源仍须符合有效名单；签名模式还需来源证明。仅知道 Hub URL 不能获得设备访问权。

已有设备不会因升级被强制归属用户，保持「未分配用户」并沿用全站策略。管理员可以在设备的「更多 → 关联用户」中分配。**关联或变更归属会撤销原手机配对并断开连接，必须重新扫码**，避免把旧手机权限带给新使用者。建议新电脑直接使用已选定用户的登记码，避免事后重新配对。

## 按设备查看和管理

「设备」列出已登记的电脑，包括在线／离线、手机配对状态、所属用户、最近上报时间、电脑工具、会话计数及 Hub 与电脑的指令往返延迟。可以按用户、状态或名称筛选，点击刷新读取当前状态。手机目前显示为电脑的配对关系，不作为另一套独立手机资产清单。

| 操作 | 效果 |
| --- | --- |
| 禁用用户 | 断开该用户所有关联电脑与手机的远程连接，拒绝后续访问和该用户登记码的新登记；保留配对关系，重新启用后可恢复 |
| 封禁设备 | 只针对所选电脑，撤销配对并阻止同一设备 ID 连接；解封后需要重新配对 |
| 撤销绑定 | 原手机失去访问该电脑的权限，需要重新扫码 |
| 临时断开 | 断开当前连接，电脑可能自动重连；持续停用应选择禁用用户或封禁设备 |
| 撤销登记码 | 阻止尚未使用的登记码继续登记，不影响已经登记的电脑 |

这些操作不终止电脑本地已经执行的任务。用户名和备注修改不会断开连接。配对状态与是否允许访问分别显示：「已配对」的设备也可能因用户被禁用而无法使用。

用户禁用范围取决于已关联的设备和登记码。不要把未分配用户的通用登记码交给需要按用户管理的使用者；系统不会根据姓名、IP 或地理位置猜测设备属于谁。

## 为某个用户单独授权

在用户的「管理 → 远程来源权限」中选择：

- **跟随全站策略**：使用「访问策略」中的全站来源名单。
- **为该用户单独设置**：分别设置本站 API、其他中转站 API、反代账号来源地址，以及官方账号开关。该配置完整替代此用户的全站来源名单；空名单关闭对应类别，不自动与全站取并集。

这可以单独放开某个来源，也可以进一步收窄某个用户的权限。只填写完整 API 地址，不填写账号密码、API Key 或机场订阅。地址的规范化、路径范围和数量要求见 [远程使用授权](REMOTE-SOURCE-AUTHORIZATION.zh.md)。

全站暂停远程执行仍优先，来源签名要求、可信发行方配置、设备配对和电脑端验证继续生效。单独名单不能自行添加可信发行方，也不能绕过封禁。修改权限会更换该用户设备的授权版本，断开连接并要求刷新授权；其他用户的单独名单不变。

仅主管理员可修改用户、关联设备和签发／撤销登记码；运维和只读协作者只能查看用户档案。修改需要填写操作原因，结果记入操作审计。旧页面保存时若遇到版本冲突，输入会保留；取消编辑、刷新，再核对最新资料后保存。

## 兼容和数据保存

- 用户档案适用于 Station 的普通扫码设备。Bot 设备使用整组手机凭据，目前不支持按单台电脑关联或迁移用户；管理页隐藏相应入口，后端也拒绝这种操作。Bot 仍可查看设备、封禁设备和管理绑定组。撤销 Bot 邀请只停止新增绑定，不会自动撤销现有手机凭据。
- 配套电脑端需要本次更新：通过已保存的本站设备凭据读取个人有效策略，凭据不会跟随重定向或跨站发送。单独授权采用 `station.guard.v2`；旧 Bridge 需升级。手机沿用现有配对协议，本次无需增加账号登录。
- 用户档案、归属和配对撤销标记写入数据卷的 `managed-users.json`。登记码、设备和管理员账号使用各自持久文件；备份应覆盖整个数据卷，恢复时保持同一批文件。
- 用户配置先持久保存再改变有效权限；保存失败不会报告成功。设备换绑的撤销标记会在重启后继续阻止原手机凭据，即使中断发生在两份数据文件之间。
- 用户被禁用时，持有有效配对的手机读取设备会收到 `423 / user_disabled`，保留原配对并提示联系管理员。无效、撤销或换绑后的凭据仍按原认证失败流程处理，不能借此恢复权限。
- 当前上限为 128 个用户档案、10,000 条设备归属、256 个未过期登记码；这些是数据保护限制，不是并发承载承诺。
