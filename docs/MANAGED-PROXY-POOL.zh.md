# 托管订阅与代理池使用说明

2026-11-07。本地实现与测试记录；尚未发布到生产 VPS。配置发布、恢复命令和观测接口见 [安全发布与运行观测](EDGE-SAFE-RELEASE-AND-OBSERVABILITY.zh.md)。

## 管理员与普通用户

普通用户填写公开 Hub URL，继续按原流程登记、配对。手机和电脑都不接收订阅、代理密码或节点选择器。管理员在“服务器”接入受控入口，在“线路”的订阅管理添加自己的公网 HTTPS 订阅。

实际路径为 `手机/电脑 → 公开 HTTPS 入口 → Edge → 指定代理节点 → 固定 HTTPS Hub`。代理池调度的是入口到 Hub 的部分。普通机场出站订阅不会自动提供公网入站转发能力；将入口装在原 Hub VPS 只能验证功能，不能证明用户到 VPS 的跨境路线改善。公开域名、TLS 和反向代理仍由部署配置提供。Edge 给回源请求附带循环标记；若回源误指回本入口或另一个 Edge，下一跳立即返回 508，不让环路耗尽容量。本版链路只允许单个 Edge。

## 一次接入流程

1. 在服务器页填写 SSH 主机、用户和密码或私钥，核对主机指纹，运行预检，再按生成的方案部署 Edge。它使用独立低权限用户，控制面监听回环地址。
2. 接通公开 HTTPS 到 Edge 的用户监听口，固定回源指向原 Hub。按部署文档配置 SSE、不缓存流式响应和可信转发头。保留 SSH 独立恢复通道。
3. 订阅页添加名称、HTTPS 地址和更新周期。默认 6 小时，允许 5 分钟至 7 天。地址保存后不回显，更新表单留空表示保留原地址。
4. 使用复杂协议前，点击安装受管 Mihomo。下载只来自固定官方版本，校验固定 SHA-256，不接受浏览器指定可执行文件地址。
5. 刷新订阅，查看每个候选节点的兼容性和新增、更新、改名、删除差异。选择最多 32 条活动线路，验证通过后应用。节点目录与活动池分离；每个来源最多 256 个候选，最多 16 个来源。
6. 日常使用主备、延迟优选或负载均衡策略；地区标签是管理员提供的筛选条件。策略或节点手工变更先测通，再进入 120 秒试运行，确认后保留；失联或未确认自动回退。

旧“订阅检测/快照导入”继续保留，仍只导入原生 HTTP/SOCKS 节点。持续更新和复杂协议应使用新的“订阅管理”，两种入口的范围不能混淆。

## 支持矩阵与检测含义

| 格式或协议 | 当前适配范围 |
| --- | --- |
| 来源格式 | Clash YAML/JSON 内联 `proxies`；URI 列表；Base64 URI 列表。订阅中的规则、provider、脚本、TUN/DNS/监听配置不执行 |
| HTTP/HTTPS、SOCKS5/SOCKS5H | Edge 原生传输；可带用户名和密码 |
| SS | 基本 cipher/password；不接入插件、链式代理或自定义文件 |
| Trojan | TLS、SNI、ALPN、指纹；受支持的 TCP/WS/gRPC 选项 |
| VMess | UUID、cipher、alterId、TLS、servername；Clash TCP/WS/gRPC；VMess JSON URI 当前为 TCP/WS。数值/字符串 alterId 严格校验，未知字段拒绝 |
| VLESS | UUID、flow、TLS/Reality、servername、指纹；TCP/WS/gRPC 受支持选项。URI `encryption=none` 可识别，其他加密选项拒绝 |
| Hysteria2/hy2 | 密码、SNI、ALPN、obfs/obfs-password；当前不接受带宽 up/down 等未适配字段 |
| 外部 Mihomo | 管理员手工填其 mixed/SOCKS 监听地址；作为一个外部代理组，不能把内部自动切换冒充已观测的单个节点 |

支持协议名称并不代表所有协议变体都支持。适配器拒绝不认识或无法保持语义的字段；内核随后进行真实配置检查，候选还须通过固定 Hub `/salcara-hub/statusz` 的 HTTPS 请求。格式兼容、内核已安装和真实回源成功在状态中分开表示。禁用节点不会被候选发布自动启用，其验证发生在重新启用的发布流程中。

订阅获取、DNS 和代理目的地址都受公网边界检查；TLS 验证不能被订阅关闭。域名解析结果中存在私网地址时拒绝，验证后的 IP 用于连接，TLS 仍保留原域名。复杂协议端口只监听 `127.0.0.1`，每条活动节点使用独立且带随机认证的 HTTP 入口。并发请求不会争用同一个可变 selector。

## 更新和失败恢复

订阅默认手工核对后应用。启用自动应用后，仅更新之前已选择、仍能匹配的节点；新节点留待选择，删除了活动节点的候选必须核对。空响应、损坏配置、重复身份、测通失败、磁盘错误或版本冲突均不能清空活动池。

节点身份不依赖显示名或密码；改名、认证轮换保留管理员的名称、禁用状态、地区、权重和容量。无法区分的重复节点明确拒绝，不按名字猜测合并。刷新失败有错峰和最高 64 分钟退避；同一 Edge 的来源维护任务不会重叠。

托管内核固定为 Mihomo `v1.19.33`，适配 Linux amd64/arm64、Windows amd64。最多两个在线代际：候选验证通过后接新流量，旧代际等已有连接排空。排空未完成时下一次发布返回等待状态，不强行切断长流。崩溃后按有上限的退避重启相同监听配置；启动异常、恢复失败在管理状态显示。Linux 使用父进程退出信号，Windows 在启动前建立私有 KillOnJobClose 归属，父进程被强杀时内核子孙进程随之退出；不扫描或停止其他 Mihomo 实例。

运行配置落在仅服务账户可读的数据目录。订阅 URL、原始节点和历史内核清单保存在 AES-GCM 加密注册表；供内核使用的运行配置必须以私有明文文件存在，进程退出/排空后清理，重启从加密清单重建。失败候选也清理，不无限累积含密码的目录。发布先持久化候选清单，再原子提交池版本；崩溃后依据已提交的池版本恢复实际节点。

回滚前必须具备对应来源和内核代际；恢复不可用时保留当前配置并显示失败，不假报成功。历史仍引用的来源不能删除。默认最多保留 8 个配置历史，所需加密内核清单随历史保留；内核运行进程数量不随历史数量增长。回滚不能重新开放当前明确禁止的直连。

## 自动调度、并发和诊断

- 自动检测默认每批结束后 30 秒再测；单节点超时 6 秒，连续失败 3 次摘除，连续恢复 2 次并等待 5 秒后重新参与。参数可配置，页面显示下次检测和本轮进度。
- 启用节点、全部活动池节点和单节点均可检测。管理员可按本轮任务 ID 取消，不把取消当作节点故障，不停止后续自动检测。
- 普通健康检测、配置发布预检、订阅候选测通共用 4 个网络探测额度。探测数量有界，业务转发使用独立容量控制。
- 延迟优选使用实际测量和平滑值、切换冷却与改善门槛。地区优先使用手工标签；可选本地 DB-IP Lite 观察服务器地址的国家 / ASN，并明确开启后用于地区过滤。过期或冲突数据按未知处理，地理距离不能代替实测收益。详见 [网络归属说明](NODE-NETWORK-OBSERVATION.zh.md)。
- 负载均衡按权重和实际在途占用分配新连接；短请求和长流分别限制，队列有界且有超时。不会自动重复发送 POST，也不把一个已断 SSE 连接“迁移”到新节点。
- 运行观测保留近 24 小时、每分钟一个聚合桶，可选单节点；显示实际计数增量、容量状态和选路理由。没有样本时显示未采集，不生成虚构的成功率或 p95。写盘失败只降低观测能力，不阻塞转发。
- 公开 `/salcara-hub/status` 显示当前访问者的站点可达性。手机连接状态入口提供手机↔Hub、Hub↔配对电脑、整段回显往返；有鉴权、限频、取消和脱敏分享，不暴露代理或其他用户设备。

## 部署与运维边界

Docker 和 SSH 受管 Edge 的内存预算调整到 512 MiB，容纳候选与旧内核同时运行。这是资源上限，不是容量承诺；正式部署应按并发、长流和订阅规模测量。Docker 使用非 root 用户、只读根文件系统、独立数据卷和无额外 capabilities，不需要 TUN 权限。

备份必须同时保护 Edge 数据卷内的 `edge-pool.json`、`sources.enc`、`sources.key` 和内核安装清单。密钥不能只备份一半；不要把这些私有文件放进公开仓库或诊断导出。迁移应先停止该 Edge，复制完整私有数据卷，再在同架构环境恢复；恢复后按 UI 重新测通，不把历史成功当作当前可用。

当前提供本机原子持久化、独立 SSH 恢复、[同一 Hub 多入口切换](MULTI-INGRESS-HA.zh.md) 和 [订阅来源共享并发额度](SUBSCRIPTION-SHARED-CAPACITY.zh.md)。Hub 管理台已支持主管理员、运维、只读及监控角色和持久管理审计；线路、订阅和服务器凭据仍仅由主管理员配置，独立 Edge 控制面不提供这些角色的逐项委派。跨来源 / 跨 Edge 共享配额、带宽公平性、按用户运营商自适应分组和自适应容量仍不在当前能力范围。监控接口及告警规则已提供，外部采集器、通知渠道和独立 Edge 数据备份仍需部署，见 [运维与恢复](OPERATIONS-AND-RECOVERY.zh.md)。Android 本地测试包已构建；自动 DNS/TLS 首装、正式签名与真机、跨境网络试点仍需完成，不能把本地通过当作商用全面放行。

## 已执行验证与上线门槛

自动测试覆盖解析边界、密文存储、版本冲突、订阅失败保旧、策略无可用路由拒绝、崩溃窗口恢复、历史依赖保护、检测取消与共享预算、恢复和观测。真实 Mihomo 测试验证两条独立监听上的并发分流、认证、Shadowsocks HTTPS 回源、错误候选隔离、进程崩溃重启、排空清理和旧代际重建。上述核心传输测试同时在 Windows 和非 root、只读根文件系统的 Linux 容器中通过。其他复杂协议的供应商互通仍须分别试用，不能据此宣称全部节点变体已实测。

管理界面按现有手机应用的颜色、品牌与控件风格统一，进行 320/390/1440 宽度明暗主题浏览器检查。手机诊断完成生命周期、权限、超时、离线和兼容状态测试；已生成的截图与浏览器报告只代表本地验证。

商用发布前仍要在目标 VPS 完成 DNS/TLS、长流、重启、升级/备份恢复与持续负载演练，并从真实国内宽带和手机网络对比直连/代理的端到端延迟、失败率、重连与恢复时间。没有生产路由数据，本地测试不能证明回国提速幅度或 SLA。
