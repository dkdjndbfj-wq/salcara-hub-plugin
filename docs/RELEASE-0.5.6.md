# Salcara Hub 0.5.6

本版配套 Salcara Android **1.8.6（versionCode 27）** 和 Salcara Desktop / Bridge **1.6.9**。正式资产、镜像、签名和实际下载须按发布记录核验；本文不表示用户线上 Hub 已升级。

## 任务恢复与待发撤回

- 保留原操作编号和票据恢复结果。明确要求桌面升级的拒绝不再显示为结果未知；已保存结果优先于新任务准入检查，不会因票据后来过期而被误报为未发送。
- 正文到期或清理后，仍保留结果未知、结果截断及已撤回的事实；未知任务不自动重发。审批响应也保留原操作编号和明确的未知结果，重试、查询与重启不会另发一次任务。
- 新增 `commands.queue-cancel.v1`：配套客户端可撤回仍在 Hub 等待派发的任务。撤回与派发竞争同一条队列记录，必须持久提交成功才确认；已经开始派发的任务不能冒称撤回成功，也不会自动发送停止 Agent 的命令。停止等待、撤回待发、停止任务是三个不同动作。
- 修复前排离线任务阻塞后续在线电脑的问题。队列容量不足会在准入前明确拒绝，保留原准备身份；过期、损坏且确认未派发的记录安全结束并释放正文。取消事务的写入或提交失败不会假报成功，只能查询原状态或重试原撤回。

## Bot 清理与持久安全

- Bot 组内已有手机绑定的电脑按已配对设备处理；撤销邀请不等于解绑。清理过期电脑后同步释放组成员名额，写入失败与重启恢复保留原身份和撤销边界，不让半完成的清理恢复旧权限。
- 管理页显示操作身份、回执和消息批次等安全记录的数量与上限，并区分设置保存失败和设置已保存但清理未完成。到期内容清理不会删除防重复执行身份，也不会提高既有限额。
- 保留公开服务发现与设备授权的区分：旧凭据不应把健康 Hub 隐藏为不可用；正常重启保留原 Hub 身份，新空数据目录仍代表另一个实例，不能自动信任或复用旧凭据。

## 设备登记失败恢复

- 站点登记持久化失败统一返回 HTTP 503 与 `remote_unavailable`，不把尚未安全保存的设备报告为登记成功。
- 用户归属保存失败且尚未建立设备时，在同一锁区内恢复原登记码，保留原用户和到期时间，可用原身份重试并跨重启恢复。登记码写入失败不会提前新增用户归属；反复更换设备编号也不会积累孤儿归属。
- 若恢复登记码本身也失败，继续拒绝登记并提示联系管理员获取新码。进程崩溃或未知结果不自动复活已消费的登记码；管理员撤销与停用仍然有效。

## 升级与验证范围

沿用既有 Ed25519 发布身份 **`salcara-local-20260930`**，不提高最低兼容门槛、不新增强制更新，不覆盖旧版本资产或旧协议更新源。公开首页和状态页共用配套版本清单；清单嵌入 Hub 构建，发布源码或客户端不会自动更新服务器页面。

恢复与队列修复基线已有 Go 各包回归、定点竞态检查、`go vet` 和管理界面逻辑测试记录。另通过本地 HTTP 发现、身份、路径前缀和临时反向代理检查，确认停机 503 与代理错误不会被包装成 Hub 成功响应。这些证据不代替候选源码的最终检查、正式双架构构建、签名或公开下载验收。

尚不据此宣称 Android 真机、真实 Agent 任务、公网代理链路、完整 arm64 运行或真实手机端到端验收通过。实际部署前按 [发布维护流程](STANDALONE-RELEASE.zh.md) 核验正式资产，再按 [Docker 部署说明](STANDALONE-DOCKER.zh.md) 升级。
