# 全站远程使用授权

当前开发源码提供全站统一授权，控制已配对用户可以通过此 Hub 使用哪些模型来源。这里的反代是模型账号的 API 来源，与服务器线路页里的 SOCKS5／Mihomo 代理池分别配置。

管理员也可以给关联了电脑的用户设置单独来源名单，见 [用户与设备管理](USER-MANAGEMENT.zh.md)。该用户名单替代全站来源名单，但全站暂停和签名验证要求仍优先。公开状态页继续展示全站默认值，不公开用户资料或单独授权。

## 管理员如何设置

打开管理台的「访问策略」页面，在「远程使用授权」中设置：

| 控制项 | 允许范围 | 关闭后的行为 |
| --- | --- | --- |
| 本站 API | 本站完整 API 地址名单 | 该名单内的普通 API 账号不可远程执行 |
| 其他中转站 API | 明确允许的外站完整 API 地址名单 | 外站普通 API 账号不可远程执行 |
| 反代账号 | 明确允许的反代完整 API 地址名单 | 反代类型账号不可远程执行 |
| 电脑本地管理的官方账号 | 受支持的本地官方账号连接器 | 官方账号不可远程执行 |

各项独立生效。前三项开启后每行填一个地址，不填写 API Key、密码或订阅链接；空名单表示关闭该类。前三份名单合计最多 32 个不同地址，每份最多 32 行，单个地址最多 4096 字节。本站与外站 API 名单不能重叠；同一服务确实同时提供普通 API 和反代账号时，可分别加入普通 API 与反代名单。

地址保留完整路径。例如 `https://api.example.com/team-a/v1` 规范化为 `https://api.example.com/team-a`，不授权 `/team-b` 或其他路径。主机大小写、默认端口、末尾 `/` 和 `/v1` 进行规范化；不接受通配符、账号密码、查询参数、片段、点路径或模糊编码。

点击「保存远程来源」后生效。草稿不会被后台刷新覆盖；保存失败保留输入。过期页面不能覆盖其他管理员已经保存的版本，需要主动重新载入。此操作仅限主管理员，复用管理写操作的审计及原子保存机制。

## 三种验证方式

- **按来源名单开放**（`open`）：仍需设备认证，由受支持的电脑端核对实际账号类型、完整 API 地址和当前配置。不会因关闭签名验证而开放任意来源。
- **来源名单 + 签名验证**（`restricted`）：在名单检查之外，每次执行还需取得可信发行方的短期来源证明。签名绑定设备、绑定关系、请求、命令内容和当前策略版本。普通 API／反代来源需要实际接入来源发行服务；受支持的官方账号走电脑确认与 Hub 短期授权。
- **暂停远程执行**（`disabled`）：停止受理新的模型任务、模型查询、消息发送和审批。连接状态、历史及安全停止操作保留；不会强制终止电脑本地已有任务。这不是封禁设备或关闭全部工作区工具的开关。

名单或模式变化会更换策略版本，旧授权不能继续用于新请求。已经开始执行的任务不会因修改名单被强杀。三端应使用同一批兼容版本，手机会展示电脑返回的拒绝原因。

「暂停远程执行」对所有版本的 Bot 和配对入口均生效，历史兼容不能绕过总暂停。v2 分类规则同样应用于 Bot 入口。Bot 通过已认证的组和手机绑定代次取得来源授权，不要求另外扫码配对；换手机、撤销绑定或换组后，旧来源授权不可复用。电脑还会核对当前连接的认证代次，断线重连不等于恢复旧授权。

## 状态说明

公开首页和服务状态页提供四类来源的开放及授权状态，直接读取当前生效的本站策略。公开摘要只含固定类别与状态，不含来源地址、账号、密钥、发行方信息或配置数量；「授权就绪」不代表上游在线或具体账号可用。首页随连接检查读取，状态页合并到每 30 秒的公开状态请求；后台或离线时暂停，不增加账号探测、后台采集或服务端历史。旧版接口未提供摘要、请求失败时显示待确认，不沿用旧授权冒充当前状态。

每类来源单独显示「已关闭」「暂停」「按名单开放」「电脑验证」或签名配置覆盖数。签名覆盖要求来源类型、完整 API 地址、来源 origin 与同源授权 URL 均正确，并在发行方声明的每个 Agent 范围内恰好匹配一个发行方。同一地址可分别由 Codex 和 Claude 的发行方负责，但范围不能重叠；配置就绪不代表允许未声明的 Agent。

「签名配置已就绪」仅代表配置匹配，不代表服务已连通、凭据可用或用户有额度。缺失或重复匹配会显示尚需配置，不会用发行方总数量冒充覆盖数量。真实执行还会核对发行方签名、命令、时间、Agent、账号配置和当前授权。

## 部署与升级

新分类使用 `StationPolicy version: 2`；电脑端必须声明 `station.guard.v2`。旧 Bridge 会被明确拒绝执行并要求升级，不能静默忽略新字段。Hub 和电脑端继续接受历史 v1 策略，但 v1 不允许夹带 v2 字段。

旧 v1 使用同一份 `apiBases` 授权普通 API 与反代，并保留历史 Bot 的来源策略行为。管理台载入旧策略时，将旧范围分别显示到本站 API 与反代名单，保留既有范围；管理员首次保存后写成 v2，Bot 也进入统一来源授权。需要限制反代时主动关闭或缩小反代名单。

管理员选择保存于数据卷 `remote-access-mode`。发行方公钥、受众等仍来自部署配置。设置 `SALCARA_HUB_REMOTE_ACCESS_MODE` 后管理台只读，需通过部署配置调整。部署策略或公开地址改变后，旧管理台来源覆盖失效。

不额外启用签名的 v2 策略文件示例：

```json
{
  "mode": "open",
  "revision": "r1",
  "station": {
    "version": 2,
    "apiBases": ["https://api.example.com/team-a"],
    "externalApiBases": ["https://partner.example.com/team-b"],
    "reverseProxyApiBases": ["https://proxy.example.com/team-c"],
    "allowOfficialAccounts": false
  }
}
```

通过 `SALCARA_HUB_REMOTE_ACCESS_POLICY_FILE` 指定文件；部署策略文件仍限制 32 KiB。切换 `restricted` 前，按照 [来源发行服务](SOURCE-ISSUER-SERVICE-20261015.md) 部署真实发行方，并配置其 `publicKey`、`origins`、`apiBases`、`sourceTypes`、`authorizationUrl` 和 Hub `audience`。`site_api` 用于普通 API（本站及外站），`verified_proxy` 用于反代类型。不要仅把示例地址换成第三方站点，就假定对方已经支持签名授权。

## 商业部署的信任边界

这是兼容客户端与来源发行服务共同执行的业务规则。`open` 依赖可信电脑端检查；来源签名能证明发行方对该请求的授权，但不能证明被恶意修改的电脑最终使用了哪家上游。若商业计费或租户隔离必须抵抗用户修改客户端，模型流量需要经过受运营者控制、可验证来源的执行服务或网关；当前源码不宣称具有远程硬件证明能力。

本轮已经覆盖分类互不串用、旧电脑拒绝、策略撤销、过期保存、持久化重启和浏览器交互，也验证了最长地址与 JSON 转义后的保存、读取、发布及签名边界。真实第三方发行服务接入、三端联合安装和生产部署仍需在实际环境验收。
