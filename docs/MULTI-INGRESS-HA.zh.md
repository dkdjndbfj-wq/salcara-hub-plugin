# 同一个 Hub 的多个 HTTPS 入口

管理员可以给一个 Hub 配置最多 7 个备用 HTTPS 入口。电脑和手机继续保存原来填写的 Hub URL、配对身份和设备凭据，自动选择连接目的地址。此能力用于入口故障切换，不等于在另一台机器运行一个具有不同数据目录的 Hub。

实际链路是：用户客户端 → 管理员控制的 HTTPS 入口 → Edge → 可选代理节点 → 固定 Hub。VPN/机场订阅提供出站代理，本身不会变成用户可以连接的公网 HTTPS 入口。备用域名、证书和 Edge 到原 Hub 的转发需要先配置好。入口经营者仍是受信任的基础设施；Hub 签名证明用于确认转发到相同 Hub，不会使一个不可信的 TLS 终止代理获得端到端保密能力。

## 管理和发布

- 部署配置 `PublicURL` 必须是公网 HTTPS Hub 地址；不能从请求 Host 推导。未设置时保留原来的单地址行为。
- 管理 API 为 `/salcara-hub/_admin/v1/ingress/state`、`save` 和 `verify`，均受现有管理会话保护；写操作同时经过 CSRF 和配置 revision 检查。
- `save` 全量提交备用列表、启用状态和优先级。优先级范围 1–1000，数字较小优先。保存新增地址不会直接发布。
- `verify` 异步验证全部启用入口或指定入口，最多并发 2 个；单入口最多 5 秒，整体最多 30 秒。
- 只有启用且已通过身份验证的入口才出现在公开清单。编辑 URL 会清除该入口验证结果。验证失败不会把错误入口加入清单。
- 清单始终包含原地址，最多 8 项。停用多入口后只发布原地址；已缓存客户端会在下次成功刷新清单时收敛，最晚受 24 小时清单有效期限制。

入口管理独立于服务器列表中当前选中的 Edge 控制器。切换管理对象不会改变用户的公网入口。

## 身份与客户端行为

Hub 在私有数据目录的 `ingress-registry.json` 持久保存独立 Ed25519 身份。正常重启不更换密钥；损坏的注册文件会停用多入口能力并显示错误，不会偷偷生成另一套身份。备份该文件必须按私钥处理。部署原地址改变时自动关闭多入口并清除入口验证状态。

旧版客户端只直接从最初配置的 HTTPS 原地址获取 `GET /salcara-hub/v1/ingress/manifest`，不跟随重定向，也不在发现请求中发送用户凭据。清单包含公开密钥、Hub 实例 ID、原地址、revision、有效期和入口列表；有效期为 24 小时。备用入口不能靠未签名列表刷新或延长信任。

新契约在 version 1 清单上增加 `signed_payload` 和 `signature`，由已固定的 Hub 公钥签署完整列表。支持 `ingress.signed-manifest.v1` 的客户端可验证候选入口返回的签名载荷、身份、有效期和完整 URL 成员关系，再验证新 nonce 证明。不能只凭“同一个公钥能响应挑战”就向新入口发送凭证；转发代理也可能中继挑战。精确字节格式、路径规则和兼容行为见[远程发现与身份协议](REMOTE-DISCOVERY-CONTRACT.zh.md)。此能力需要配套客户端，不自动改变旧客户端的刷新逻辑。

客户端在给备用入口发送业务请求之前，通过 `GET /salcara-hub/v1/ingress/identity?nonce=...` 获取 Hub 对随机挑战的签名。签名包含实例 ID、随机 nonce 和 30 秒有效期；同 ID 但签名错误、旧 nonce、过期证明和重定向都会被拒绝。协议时间均为 Unix 毫秒，最多容忍 5 秒未来时钟偏差。原始 HTTPS 地址本身就是用户信任根，不增加这一轮身份预检；旧版 Hub 缺少该可选端点也不会阻止原地址继续工作。

桌面 Bridge 普通 HTTP 与 SSE 共用透明路由层：

- 每小时尝试直接刷新清单，失败后一分钟再尝试；最多缓存 16 个 Hub，重启可以继续使用未过期缓存。
- 发现/证明单次请求最多 3 秒，单次选择入口的总预算为 6 秒。入口失败后在后续 30 秒内降低选择次序，仍保留恢复机会。
- GET 在传输错误或 502/503/504 时可以尝试下一入口。业务 POST 一旦交给传输层就不会由入口选择器重放；原有业务回执、去重和恢复逻辑继续处理结果不确定的请求。
- 已建立的 SSE 不在中途迁移；断线重连时重新选择并验证入口。配对、队列、附件和回执仍使用原 Hub 身份。
- 原地址故障超过清单有效期后，客户端停止使用缓存备用地址。首次接入时原地址不可用且没有缓存，也无法凭空发现备用入口。

该机制不测量用户到每个入口的地理距离，也不声称低优先级入口一定更快。入口选择与 Edge 代理节点的健康、延迟、地区策略属于不同层；每个入口的实际收益需要从真实客户端测量。桌面使用备用入口时的身份预检会增加一次往返，这是当前实现的明确成本；原地址没有这一额外往返。

## 验证范围

自动化覆盖持久身份、管理鉴权/CAS、错误签名与 nonce、过期和重定向拒绝、验证并发取消、磁盘写入失败保留旧配置、只发布验证入口、桌面无 POST 重放、缓存故障切换与过期、普通 HTTP/SSE 保持同一配对身份。生产域名证书、运营商网络、长时间跨境故障以及手机实机后台切换仍需部署后验证。
