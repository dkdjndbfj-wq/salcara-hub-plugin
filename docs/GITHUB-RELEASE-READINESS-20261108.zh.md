# GitHub 发布与可用性说明（2026-11-08）

当前目标是让用户能按文档部署 Hub、连接电脑和手机并完成远程操作。商业防破解、容量认证、SLA 和完整生产运维演练不作为这次 GitHub 源码／测试版本发布的前提。此前的 [商业发布核对](COMMERCIAL-RELEASE-READINESS-20261108.zh.md) 保留作历史参考。

## 发布准备与候选版本

本轮配套候选为 Android **1.8.3（24）**、Desktop **1.6.5**、Hub **0.5.3**。各端从最终统一源码重新构建，沿用既有正式签名；历史本地测试包不作为本次正式附件。具体功能及升级要求见 [Hub 0.5.3 发布说明](RELEASE-0.5.3.md)。签名包、固定镜像与公开下载验证完成前，不将源码版本号等同已发布版本。

- Hub、电脑和手机的本轮源码改动已完成相关范围回归；管理页完成本地真实 Hub 浏览器验证。具体覆盖与限制见 [三端产品收尾记录](PRODUCT-COMPLETION-20261108.zh.md)。这些结果不代表 GitHub 现有正式版本已包含本轮改动。
- 已补修旧 v1 Bot 可越过全站暂停的问题，相关 Hub／管理后台回归通过。已有授权、配对和数据保护继续生效。
- 当前源码补充 [管理员登录与用户管理](USER-MANAGEMENT.zh.md)：管理员建用户、登记码归属、设备关联、禁用与单独来源名单；普通用户保持扫码体验。需配套更新电脑端，Bot 整组设备不支持单台改归属。
- Android 已生成带内置 JS 的 arm64-v8a 测试 APK，版本 1.8.2（23），包名 `top.salcara.image.remotetest`，使用 Android Debug 测试证书，可与正式 App 并存。该包应标为测试版；当前没有真机安装、后台及 FCM 送达结果，也没有本轮 iOS 构建。
- 上述功能验收发生于发布前；最终 GitHub 发布结果以该版本 Release 的源码、附件和构建记录为准。本次范围不包括部署用户 VPS。

## 用户怎样用

1. 管理员按 [Docker 部署教程](STANDALONE-DOCKER.zh.md) 配置 Hub 的公开 HTTPS 地址。
2. 电脑填写站点地址，手机按原流程扫码配对；远程任务仍由已连接的电脑和 Agent 执行。普通用户不需要订阅地址或选择代理节点。
3. 管理员在 [远程使用授权](REMOTE-SOURCE-AUTHORIZATION.zh.md) 中设置全站来源开关和地址名单。普通名单模式可直接使用；普通 API／反代来源选择签名模式时，需要接入对应来源发行服务。
4. 需要代理池时，再按 [托管订阅说明](MANAGED-PROXY-POOL.zh.md) 配置入口、订阅和检测。代理池是可选功能，基础远程流程可先使用直连 Hub。

## 发布时说明清楚的事项

- **版本搭配：** Hub 0.5.3 的用户独立授权需与本轮 Desktop 1.6.5 配套，不能只更新 Hub 后直接对旧 Bridge 开通。v2 分类授权要求电脑支持 `station.guard.v2`。启用或在管理台保存 v2 前应先升级电脑端；旧 Bridge 会明确拒绝执行。Release 说明列出实际搭配的三端版本和测试范围。
- **安装包身份：** 上述 Android 包供独立测试，不能覆盖正式 App。各端正式包沿用原签名与更新流程；Hub 流程见 [构建、签名与更新维护](STANDALONE-RELEASE.zh.md)。
- **基本可用性：** 推荐给普通用户日常使用前，用实际配套安装包完成一次配对、发消息／任务、审批、停止、查看结果和断线重连。当前源码回归不能记作这次真机验收；GitHub 测试版可明确列出待验证项。
- **加速范围：** 机场订阅提供出站节点，不自动提供供用户接入的公网入口。实际链路为“手机／电脑 → HTTPS 入口 → Edge → 代理节点 → Hub”，是否更快取决于实际线路；当前没有实测提速幅度承诺。

后续优先修复安装失败、连接失败、权限错误、消息丢失和界面误导等影响使用的问题，再依据实际反馈补功能。

用户禁用返回明确的 `423 / user_disabled`，保留手机配对。已有设备改归属会撤销旧手机凭据并要求重新配对；Bot 整组凭据不支持单台改归属。升级需备份同批完整数据卷（包括新增 managed-users.json），不重新初始化；启用新用户策略后不能直接降级旧 Hub 并假设权限语义仍然有效。
