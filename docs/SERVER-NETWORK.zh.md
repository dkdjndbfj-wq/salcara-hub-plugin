# 服务端入口与线路管理

此功能让管理员管理入口到 Hub 的线路。电脑和手机仍填写同一个公开 Hub URL，按原流程登记、扫码配对；不接收代理订阅或节点凭据。

## 能力与部署位置

```text
电脑 / 手机 → 公开 HTTPS 入口 → Salcara Edge → SOCKS5 / HTTP / Mihomo → 固定 Hub
```

Salcara Edge 是独立的受控入口程序，管理面与用户流量分开监听。它只能转发固定 Hub 的 `/salcara-hub` 路径，不提供任意目标代理。HTTP POST 不因线路失败自动重发；SSE 即时刷新，故障由客户端的既有恢复机制处理。

需要一个可由管理员控制的入口，或者供应商已提供的相应转发能力。普通机场订阅仅提供出站代理时，不能仅靠在 Hub VPS 安装本程序，就让用户入站流量提前经过机场节点。把 Edge 装在同一台 VPS 可以完成功能验证，但不能据此宣称改善跨境线路。

## 当前支持范围

| 项目 | 当前能力 |
| --- | --- |
| 手工线路 | 直连、HTTP / HTTPS 代理、SOCKS5 / SOCKS5H，支持用户名密码 |
| Clash / Mihomo | 可使用固定版本的受管内核和独立节点监听，也可连接已有 mixed / SOCKS 端口 |
| 订阅格式 | Clash YAML / JSON 的内联 `proxies`、代理 URI 列表、Base64 编码列表 |
| 订阅检测 | 格式、单节点兼容性、重复项、无效地址、受限字段与安全边界；不执行规则、DNS、TUN 或脚本 |
| 原生导入 | 通过检测的 HTTP / SOCKS5 节点；本次导入为快照，不保存原订阅 URL，也不自动定时更新 |
| SS / Trojan / VMess / VLESS / Hysteria2 | 新订阅管理支持经受管 Mihomo 检查和验证的协议子集；旧快照导入仍限原生代理 |
| 持续订阅 | 加密保存来源、定时刷新和差异核对；候选测通后应用，失败保留原版本 |
| 节点池 | 最多 32 条线路；手动、主备、延迟优选、负载均衡；权重、并发上限、有界队列、排空与实际占用 |
| 自有 VPS | 后台填写公网 IP / 域名、SSH 端口、用户和密码或私钥；发现指纹、预检、加密保存、方案审阅、异步安装 Edge |
| 用户访问加速证明 | 仍需实际入口及客户端对照测量；后台探测值只代表入口到 Hub |

“协议支持”“连通性通过”“用户体验改善”是三项不同的结果。检测页面不把订阅可解析显示为加速完成。

## 构建与运行

在仓库根目录执行：

```sh
go build -trimpath -o salcara-edge ./cmd/salcara-edge
```

在入口主机创建私有配置目录和独立的 256 位控制令牌文件。不要复用 Hub 管理密钥或程序更新令牌。令牌使用 64 个十六进制字符；Linux 文件权限为 `0600`，数据目录只允许运行账户访问。

```sh
./salcara-edge \
  -origin https://origin.example.com \
  -data-dir /var/lib/salcara-edge \
  -control-token-file /run/secrets/edge-control-token \
  -listen 127.0.0.1:8790 \
  -control-listen 127.0.0.1:8791
```

`origin.example.com` 是固定 Hub 回源地址，必须与公开入口分开，不能解析回 Edge 自己而形成循环。非直连线路强制要求 HTTPS origin 并正常验证证书，避免通过第三方代理明文传输 Hub 会话。HTTP origin 仅允许直连，用于可信私有链路或本机验收。

控制监听强制为数字回环地址。通过已有私有隧道，或带正常证书的受控 HTTPS 管理反代，将该控制服务接入 Hub。普通用户入口只反代 `8790`；不要把 `8791` 当普通网站开放。Docker 配置在 [deploy/edge/compose.yml](../deploy/edge/compose.yml)，采用 Linux host networking 以保留回环监听，不挂 Docker socket、不改宿主机默认路由。

现有 HTTPS 反向代理应关闭 SSE 缓冲，保留长连接超时，覆盖而不是盲信客户端传入的转发头。只有明确可信的前置反代 CIDR 才配置 `SALCARA_EDGE_TRUSTED_PROXY_CIDRS`。Hub 前如还有反代，也需要按真实、可信的回源链配置客户端 IP；不能对任意公网请求信任 `X-Forwarded-For`。

保持 `SALCARA_HUB_PUBLIC_URL` 为用户使用的统一域名，例如 `https://hub.example.com/salcara-hub`。配对身份、管理 Cookie、Origin 校验仍以这个地址为准。

## 接入 Hub 后台

为 Hub 增加以下部署配置，并只读挂载同一控制令牌：

```text
SALCARA_HUB_NETWORK_CONTROL_URL=https://edge-control.example.com
SALCARA_HUB_NETWORK_CONTROL_TOKEN_FILE=/run/secrets/edge-control-token
```

外部控制地址只能由部署配置指定，不能在浏览器请求里替换。公网控制地址要求 HTTPS；HTTP 只允许回环、私有 IP 或部署内部的单标签服务名。容器内的 `127.0.0.1` 指容器本身，跨主机或跨容器必须先建立实际管理通道。也可使用下文的“服务器”页，通过 SSH 管理已部署的 Edge，不需要公开其控制端口。

重启 Hub 后进入“线路与代理池”。未配置入口时仍可检查订阅兼容性，但不能导入到远程节点池；接通入口后重新检测再导入。

1. 添加现有 SOCKS5 / HTTP 地址，或输入公网 HTTPS 订阅地址进行检测。
2. 查看支持与不支持原因，在剩余池容量内勾选节点再导入。原订阅地址提交后清空，预览不含代理密码。
3. 执行“检测线路”，确认固定 Hub 健康端点可达。
4. 选择手动固定、主备切换、延迟优选或负载均衡；保存绑定当前入口身份与配置版本，过期编辑或切换入口后的旧表单返回冲突。
5. 通过真实手机和电脑对比延迟、稳定性与故障恢复时间，再决定对用户启用入口。

订阅仅允许公网 HTTPS；每次 DNS 解析都拒绝包含私网结果的目标，固定到经过校验的 IP，重定向重新校验。响应最多 1 MiB，抓取预算 5 秒；预览有效 10 分钟且数量有界。远程订阅不能偷偷导入内网节点，本机 Mihomo 地址需要管理员显式手动添加。

配置数据包含代理凭据，存储文件不向浏览器回显密码，按私有文件保护；订阅及 SSH 凭据另有认证加密存储。Hub 管理台已加入分角色权限、持久管理审计与离线加密备份，见 [运维与恢复](OPERATIONS-AND-RECOVERY.zh.md)。这些权限不等于为独立 Edge 提供逐项委派；Hub 归档也不自动覆盖独立 Edge 数据卷、卷外凭据及 TLS 配置。线路运行事件与管理审计的保留范围不同，长期指标、外部告警接收及完整部署恢复仍需配套验收，不能据此宣称完成合规认证。

## 切换与故障

自动探测连续失败后剔除线路，实际请求连接失败可立即触发下一次连接换线。延迟优选带改善阈值与冷却，避免细小差异导致持续抖动。普通切换影响新连接；旧 TCP / SSE 不能无损迁移，不承诺零中断。

请求连接失败和 SSE / 响应体中途读取异常计入节点故障；客户端取消不判为节点故障。每个探测结果完成后即可重新选路，不等待全池慢节点。未知节点、过期样本及故障恢复初期限制为单个在途请求；全新节点首次成功实测后可用正常容量，故障恢复和重新启用则需连续成功且满足观察间隔。自动模式可禁止未知或过期节点试探。探测间隔不等于保证恢复时限，仍不能承诺无缝或固定秒数的故障转移。

自动检测默认每轮完成后等待 30 秒，单节点超时 6 秒，检测并发 4，连续失败 3 次隔离，故障后连续成功 2 次且观察至少 5 秒恢复，样本有效 120 秒。后台可调整这些参数，支持单节点、启用节点和包括禁用节点的全池诊断。地区标签由管理员填写，自动模式支持地区优先或仅使用指定地区；目前没有按用户 IP 自动定位选路。具体顺序、范围与失败行为见 [调度与检测契约](PROXY-SCHEDULING-AND-STATUS.zh.md)。

手动、主备、延迟优选保留单条活动线路；新增“负载均衡”按在途占用与权重，在多个可用节点之间分配新请求。选择与容量预留原子完成。默认每节点短请求 64、流连接 16，全局短请求 256、流连接 128；这些是可配置上限，不是已经验证的承载成绩。队列默认最多 64、等待最多 2000 毫秒，可设为不排队。队列满返回 429，超时或无线路返回 503；请求取消及时出队，响应体结束、关闭或断开只释放一次容量。

“排空”停止给节点分配新请求，已有连接自然结束。短请求和流连接分开计数，API 已知的 SSE 路径或声明 `Accept: text/event-stream` 的 GET 请求计入流连接预算；其他长轮询归短请求。累计完成、失败、拒绝和取消为本进程实际计数，重启清零；旧节点被删除或更换后，其仍在途请求继续计入全局上限。检测并发默认 4，可设 1–16，仅用于健康探测。

后台提供可选每 5 秒状态刷新，离开页面、切后台或读取失败会停止；刷新不会启动全池探测。负载均衡不保证精确流量比例、不叠加带宽，没有按用户身份公平调度或自适应容量。VPN 订阅的共享带宽、入口和 Hub 本身仍可能是瓶颈。

## 在后台接入自有 VPS

“服务器”页提供以下完整流程：

1. 填写公网 IP / 域名、SSH 端口、用户名及密码或私钥。点击“发现指纹”时只连接握手，不发送认证凭据。
2. 通过可信渠道核对并确认主机指纹，再执行认证预检。检查 Linux、amd64/arm64、systemd、安装与探测工具，以及 root 或免交互 sudo。指纹不匹配会在密码发送前停止。
3. 保存预检结果，凭据使用 AES-GCM 加密存入 Hub 数据卷的 `servers.enc`；独立 `servers.key` 以私有文件保存。浏览器不会取得保存后的凭据。检查结果有效 10 分钟。
4. 指定独立的 HTTPS Hub 回源地址，生成部署方案；查看目录、服务、监听地址和程序 SHA-256 后点击部署。任务异步执行，每台主机最多一个任务，总共最多两个。
5. 安装成功后点击“设为线路入口”，经 SSH 访问远端回环管理端口，随后进入“线路与代理池”配置代理与策略。“使用环境配置入口”可切回原部署配置。

最多管理 16 台 VPS、保留最近 32 个部署任务。当前自动 SSH 接入仅接受解析到公网地址的主机，不支持内网地址、跳板机或交互式 MFA。远端须已有 systemd、curl、sha256sum、ss、flock、tar、install、useradd 等基础工具，不会自动升级系统或安装 Docker。

安装创建专用 `salcara-edge-managed` 账户、`/opt/salcara-edge-managed`、`/var/lib/salcara-edge-managed` 和对应 systemd 服务。只有经管理令牌哈希绑定归属的安装才允许更新；未知目录或其他 Hub 的安装拒绝覆盖。上传文件按方案哈希校验。升级失败会尝试恢复旧程序、服务配置与旧节点配置文件；首次安装失败保留可重试的归属记录。Hub 在任务执行中退出时会记录中断，重启后需先检查远端实际状态再重试，不宣称任务跨重启无缝继续。

SSH 自动部署 Edge 入口；其后可在订阅页单独安装固定版本 Mihomo。部署不包含自建 SOCKS5 出口、证书签发、DNS、防火墙或公网反向代理。远端仅监听回环 `8790/8791`；安装成功后仍需接通公网 HTTPS 到 `8790`，关闭 SSE 缓冲并正确配置可信转发头。`8791` 不对普通用户公开。管理连接断开不会主动终止远端已经健康运行的数据流。移除服务器记录不卸载远端服务。

本仓库构建的 Docker 镜像内含 Linux amd64/arm64 Edge 程序，默认路径 `/opt/salcara/artifacts`。独立二进制部署需自行构建相应程序，以 `salcara-edge-linux-amd64` / `salcara-edge-linux-arm64` 命名放入只读目录，设置 `SALCARA_HUB_EDGE_ARTIFACT_DIR`。只替换 Hub 二进制不会更新这些文件；更新入口版本前同步经过验证的配套文件。没有部署文件时 UI 会明确显示不可用，不能只靠一个填写凭据的表单完成部署。

加密文件与密钥同处受保护的数据卷：它避免注册表明文泄露，并不抵御获得整份卷或运行主机权限的攻击者。备份应同时保护这两个文件。Windows 的 Unix 权限位不能代替 ACL，需按部署环境限制文件访问。当前尚无多管理员角色分权和长期合规审计。

直连作为显式节点参与配置；需要禁止直连时禁用该节点。入口本身故障与入口后的代理节点故障是两个层面，后一层自动切换不能代替入口高可用、DNS 切换或供应商 SLA。

导入、保存或检测失败时，旧配置继续保留。配置原子替换后如果目录持久化不能确认，后台会保留相应提示。恢复前先备份私有数据目录；回滚由管理员恢复已验证配置，不删除 Hub 的设备数据卷。

## 用户查看状态

用户可访问 `/salcara-hub/status`，无需管理员密钥。页面显示本次浏览器到 Hub 的可达性与请求耗时、最后成功时间和最近 12 次页面内检测记录；默认每次检测结束后 30 秒自动再测，可关闭或手动执行。隐藏标签页 / 离线时暂停，单次超时 8 秒。不会展示代理节点或其他用户信息，也不将状态接口可达解释为手机到电脑的完整业务正常。页面与 Hub 同源，入口完全宕机时首次打开仍可能失败；独立状态站及持久可用率尚未实现。

## 验证范围

本地自动化覆盖管理认证与 CSRF、控制凭据隔离、HTTP / SOCKS5 真实转发、多代理并发、队列和取消、SSE 故障及容量释放、非幂等请求不重试、订阅限制、版本与入口身份冲突。真实本地 SSH 服务验证指纹和认证、加密存储与重启、超时取消；隔离容器运行实际安装脚本，以模拟 systemd/健康接口验证首次安装重试、文件权限和旧数据回滚。真实浏览器验证桌面与手机界面；模拟 API 的部署界面测试不等于真实 VPS 部署验证。

实际公网路由收益、供应商限额、真实 VPS 的 systemd/TLS/反代组合、容量与长时间运行仍应在目标部署试点验收。托管 Mihomo、订阅周期更新与 24 小时聚合趋势已经实现，详见 [托管代理池说明](MANAGED-PROXY-POOL.zh.md)。新增 [多入口透明切换](MULTI-INGRESS-HA.zh.md) 与 [节点网络归属](NODE-NETWORK-OBSERVATION.zh.md) 已接线并完成本地验证，长期指标平台仍属后续范围。
