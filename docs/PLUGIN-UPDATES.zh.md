# 检查更新与一键更新

这两个按钮在带 Salcara Hub 扩展的 Sub2API 宿主「插件管理」卡片中提供，不能由旧版插件自己给原版服务器增加权限或路由。

## 首次安装

先按官方 0.2.11 基线的宿主适配文档审查、备份并部署自定义宿主 `0.2.11+salcara.hub.1`。不降级到早期研究用的 0.2.8，也不将普通原版 0.2.11 当作支持 Hub 的版本。

核对公开身份 `publisher/public.json`，把发布者 ID `salcara-local-20260930` 与公钥合并进 `plugins.trusted_publishers`，保留 `allow_unsigned:false` 和全部原配置。宿主加载实际配置后，上传签名 `.s2plugin`，配置并启用；公开更新清单不会替你自动信任新公钥。

## 更新操作

1. 点击「检查更新」。只有这次手动请求联网，不启动后台轮询。
2. 页面展示当前/目标版本、宿主兼容性和更新说明。未配置更新源、未信任发布者、尚未发布清单、无更高版本或不兼容会显示不同状态。
3. 有可用更新时点击「一键更新」。运行中的插件需确认维护期会短暂断开远程连接，可选择更新后恢复运行；未声明测试过的宿主需再次明确确认。
4. 服务端重新获取清单、下载并验证大小和 SHA-256，然后由真实安装器校验发布者签名、清单及所有文件哈希，再核对同一插件 ID、严格递增版本、能力和宿主要求。任何一步失败都不会先停旧插件。
5. 校验通过才进入维护并换包，保留加密配置及宿主插件数据。成功恢复运行、已安装但未运行、并发变更/换包失败是不同状态；后者需要刷新与人工处理，不声称自动回滚。

原停用插件更新后仍停用。运行中任务不会因更新按钮而被主动终止，但中继连接会短暂中断；不要在关键远程操作途中更新。手机端不应把未知送达当成肯定未执行，不应换 requestId 重发任务。

## 更新源与安全

Salcara Hub 默认源为公开仓库 Releases 的 `update.json`，发布者 ID 固定为 `salcara-local-20260930`。没有真实 Release 时明确显示“尚未发布”，不会假报更新。

```yaml
plugins:
  # 示例条目需合并，不能覆盖现有 plugins 配置。
  update_sources:
    top.salcara.hub:
      url: "https://github.com/dkdjndbfj-wq/salcara-hub-plugin/releases/latest/download/update.json"
      publisher_key_id: "salcara-local-20260930"
```

管理员可显式为空地址关闭默认源，其他插件可配置各自来源。前端请求不能自行指定下载地址或公钥。发布者公钥必须已被管理员核对并信任；即使站点允许未签名开发包，自动更新仍强制要求固定发布者的可信签名。

下载只允许公共 HTTPS、443 端口，DNS 结果和每次连接/重定向都校验并固定公网 IP，不使用模型 API Key、调用者 Cookie/Authorization、环境代理或网关代理。清单最多 64 KiB，包最多是宿主上传限制与 128 MiB 的较小值；有超时和重定向上限，每台宿主进程只允许一个完整更新下载/换包流程。

配置、停用、替换和恢复会检查版本、二进制哈希与配置是否仍匹配，避免多个管理员/宿主实例静默覆盖。该流程没有跨服务器永久 exactly-once 和自动数据迁移回滚保证；备份和首次宿主部署仍由站点运营者完成。

## 不包含什么

- 不自动升级整个 Sub2API、替换 Docker 镜像或修改反代。
- 不把插件签名当作官方认证；不下载、共享或授权私钥。
- 不声称 APK 编译成功即代表 Codex/Claude Desktop 实机远控全部可用。
- 手机软件只在独立私有测试仓库构建，本文发布不切换正式手机更新通道。
