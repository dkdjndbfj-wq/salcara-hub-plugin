# 商业发布就绪核对（历史参考，2026-11-08）

当前范围已调整为 GitHub 源码／测试版本交付，以 [GitHub 发布与可用性说明](GITHUB-RELEASE-READINESS-20261108.zh.md) 为准。本记录保留已修复的问题及未来商业部署可参考的检查项，不再作为当前 GitHub 发布的统一阻断清单。

当时的评估结论是：尚不能声称已完成商业验收。源码回归、界面截图和测试 APK 不代表已经完成生产与真机验收。

本次核对范围是本轮三端改动、授权执行边界、代理池部署约束、发布说明及已有验证记录，不是穷尽式安全审计。未部署 VPS、发布安装包、变更更新渠道或调用真实付费模型。

## 本次确认并修复

- 旧 v1 Bot 的来源兼容分支原先位于全站 `disabled` 检查之前，导致旧配置下的新任务、发送、审批和模型查询可越过总暂停。新增回归先复现失败，随后调整检查顺序：总暂停对所有策略版本生效，状态、历史与安全停止仍可用；重新开启后保留 v1 的原来源兼容行为。
- 修复后 Hub 与管理后台 `TestStation|TestBot|TestRemoteAccess` 范围回归通过，分别为 11.061 秒与 16.915 秒。
- 纠正两份旧代理池文档中“无管理角色、无持久审计、尚无 Android 构建”的过期描述。Hub 角色及审计已经实现；独立 Edge 控制面、长期留存和外部告警部署仍有各自边界。

## 两个不能靠补界面解决的边界

**来源授权的商业用途。** 普通名单模式依赖可信电脑端实际执行；签名证明发行方授权了请求，不能证明被恶意修改的电脑最终调用了哪家上游。若收费和授权体系必须抵抗用户修改客户端，需要运营者控制、能够验证实际模型调用的执行服务或网关。此项是否属于首发阻断条件取决于售卖承诺，不能把当前名单功能宣传为不可绕过的防破解机制。

**回国加速的实际链路。** 当前代理池优化公开入口到 Hub 的部分。机场订阅不自动提供公网入站能力；把入口装在原海外 Hub VPS，并不能证明国内用户到该 VPS 的瓶颈得到改善。应按 [代理池说明](MANAGED-PROXY-POOL.zh.md) 完成受控入口部署与端到端试点，再决定是否对外开放加速。

## 若以后开展商业验收，可参考的顺序

1. 固定首发平台、功能承诺和三端候选版本；保留旧版迁移说明。
2. 部署预发布 Hub/Edge，进行真实手机、电脑、Agent、来源发行服务联调。
3. 在目标硬件完成容量、弱网、故障恢复与跨境对照测试，修复实际发现的问题。
4. 验证正式签名产物的安装升级和恢复，完成小范围灰度后再公开发布。
