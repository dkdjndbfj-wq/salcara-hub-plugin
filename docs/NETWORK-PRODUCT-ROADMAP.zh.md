# 服务端线路工具产品化路线

日期：2026-11-07。状态：持续实施中的设计基线。本轮已实现配置预检/试运行/回滚、独立恢复 CLI、托管 Mihomo、订阅持续维护、检测取消/共享预算、24 小时趋势、选路解释与手机分段诊断，并完成本地验证；尚未发布到生产。实际功能、限制和使用步骤以 [托管代理池说明](MANAGED-PROXY-POOL.zh.md) 与 [安全发布/观测契约](EDGE-SAFE-RELEASE-AND-OBSERVABILITY.zh.md) 为准。本文未逐项注明已完成的高级能力仍为规划，不能作为商用承诺。

## 产品目标与交付顺序

管理员接入一份订阅与一个受控入口，系统能说明哪些节点可用、当前为什么选它、是否改善真实用户体验，以及故障如何恢复。普通用户继续填写统一 Hub URL，完成原有登记与配对；代理选择和凭据只留在服务端。

当前已有节点调度、健康检测、容量限制、订阅快照检测、SSH 部署 Edge 与公开 Web 状态页。本轮补上受控 Mihomo、订阅持续维护、错误配置自救、分段诊断和有限持久运行记录；公开入口的 DNS/TLS 配置与实际路由收益仍需目标环境验证。

| 阶段 | 交付结果 | 放行条件 |
| --- | --- | --- |
| A：接入与恢复基础 | 首装向导、链路验证、配置版本、可恢复发布 | 能从干净 VPS 按界面完成受支持部署；填错策略后可自动或通过独立管理通道恢复 |
| B：订阅真正可用 | 托管 Mihomo、逐节点映射、订阅定时更新与差异发布 | 主流支持协议可独立探测和分流；坏订阅、更新失败、内核失败不替换最后可用版本 |
| C：诊断与日常管理 | 管理概览、真实趋势、选路原因、手机 / 电脑分段诊断 | 能区分入口、回源、电脑离线、鉴权和服务拥塞，并提供对应处理办法 |
| D：有数据依据的自动优化 | 质量调度、分组容量、地域观察、多入口试点 | 真实对照数据证明收益；公平性、抖动、回退与入口故障通过演练 |

A 与 B 构成第一版可独立维护的交付目标，C 的基础诊断随之交付。长期运营能力逐项纳入发布门槛，不把全部高级功能绑在一次大版本中。阶段顺序依据依赖关系，不预报未经工作量评估的完成日期。

## A. 让管理员能部署，也能恢复

### 首次配置流程

沿用现有“服务器”接入、指纹核对、预检和 Edge 部署能力，串成连续流程：

```text
接入服务器 → 检查环境 → 配置公开入口与固定 Hub
→ 检查 HTTPS / 回源 / 长连接 → 添加订阅或代理
→ 查看候选线路 → 试运行 → 应用 → 给用户统一 URL
```

页面分别报告“服务器可管理”“入口公网可达”“回源可用”“线路已验证”，并指出尚缺环节。回源地址不能指回公开入口而形成循环，证书主机名、端口、路径和 SSE 缓冲都纳入检查。

部署分为受管独立入口与使用现有反代两种方式。受管方式仅操作本项目拥有的资源；遇到既有 80/443 服务时提供匹配其部署方式的配置步骤，不覆盖未知站点。DNS / 证书外部权限仍需管理员提供，界面显示可执行的下一步。普通出站订阅不能代替公网入口，只有本机回源成功也不能显示“公网已加速”。

### 配置版本与自救

高风险改动采用“草稿 → 校验 → 临时应用 → 确认生效”，记录版本、操作者、变更摘要及上一个已验证版本。候选发布前试走固定回源，避免“仅使用某地区”却没有任何候选节点。

建议临时应用默认保留 120 秒确认窗口，最终时间由集成测试校准。计时与待确认状态由 Edge 持久化；浏览器关闭、Hub 控制面掉线或 Edge 重启不丢失恢复责任。未确认或验证失败则回退，回退使用版本比较，不覆盖期间已经完成的更新。失效凭据不能被标为可用回滚版本。

日常自动订阅更新沿用已授权的更新规则，候选验证失败自行保留旧版，不要求管理员每次在线确认。只有超出规则的变更进入待审阅状态。

管理通道通过独立 SSH / 私有控制面保留；提供本机恢复命令，可查看当前版本并回退。恢复不依赖被错误代理策略阻断的用户入口。策略原本明确禁止的直连不能因“自救”偷偷开放；回退恢复原来已验证且被允许的配置。

验收覆盖：限制到空地区、全池禁用、错误凭据、回源循环、应用中断、回滚期间重启、更新与回滚并发。现有健康长连接继续完成，恢复不自动重发执行指令。

## B. 把订阅变成持续可用的节点资源

### 托管 Mihomo 与节点归属

Clash Verge 是客户端，兼容能力按固定 Mihomo 内核版本及其实际配置验证结果定义。首批支持列表按协议与选项组合发布；不能因为认出 SS / Trojan / VMess / VLESS 名称就宣称所有变体可用。

默认由 Edge 统一选路，Mihomo 负责复杂协议传输。受管模式将每个活动节点绑定到确定的本地代理监听入口，使健康样本、并发占用和实际出站节点一一对应。先对选定内核做能力验证：独立监听能否固定到指定节点、并发连接是否隔离、替换配置是否影响旧连接。

**不采用“每次请求前改一个共享 selector”的方案**，否则多个并发请求可能互相改路。若固定版本无法提供所需隔离语义，则采用有界独立实例分片，或明确将其作为一个整体策略组；不得在 UI 虚构逐节点调度。

现有用户自己配置的 mixed / SOCKS 端口继续可用，标为“外部代理组”，内部节点切换不冒充 Edge 已观测到的逐节点选择。这修订原总体设计 8.3 节的默认职责：受管模式优先固定逐节点映射，外部模式保留整体线路兼容。

内核安装固定来源、版本与校验值，记录再分发许可处理；不接受订阅控制 TUN、脚本、任意资源抓取或管理监听。候选内核使用独立受限进程和端口，管理端口不面向公网。新版本通过 HTTPS 回源与长流验证后承接新连接；旧版本排空期间受进程和内存预算限制。排空超时及供应商凭据立即失效导致的重连必须可见。

### 订阅记录与自动更新

为订阅建立独立记录：名称、加密的源地址引用、启停、更新时间、上次成功、下次计划、候选差异和发布版本。保留现有公网 HTTPS 抓取边界、响应上限与协议白名单。

建议默认每 6 小时拉取一次，随机错峰，支持手动刷新与条件请求。失败采用有上限的退避，任务不能重叠；拉取、解析、测通与发布分别显示结果。供应商确实返回流量 / 到期信息时显示来源和更新时间，缺失时显示“未提供”。

更新按来源与稳定身份匹配，改名不丢管理员的地区、权重、分组与禁用设置。认证变化生成新的传输配置版本；无法可靠匹配的项列为增删待审阅，不仅按显示名合并。手工节点与订阅节点分开归属。

默认允许验证通过的新增 / 更新进入候选池；远端删除先停止新分配并排空。空响应、解析失败、全部节点失效或大规模删除不得直接清空当前池，需明确告警并保留旧版。旧版也失效时如实显示不可用。

### 大量节点的管理

把“订阅节点目录”与“承接业务的活动池”分开。第一版保持当前 32 条活动线路的边界，目录容量另行配置并压测；超过限额明确提示，不静默截断。提供搜索、协议 / 地区 / 状态筛选、批量禁用、批量打标签、候选选入和更新差异。

活跃节点保持较及时的探测，备用目录使用有界轮转和退避；“全部测通”作为可取消、可显示进度的后台任务运行，管理员离开页面不丢任务状态。任务间共享探测预算，不能绕过并发上限；大量节点不保证在单个固定周期内全部测完。

验收覆盖：重复节点、改名、认证轮换、节点删除、超大或损坏订阅、供应商限流、内核崩溃、发布失败、Hub / Edge 重启与长流排空；每条节点的检测与真实转发必须一致。

## C. 管理员与用户能看懂发生了什么

### 管理界面

保留手机应用的设计语言，将线路页的日常信息与低频配置分开。管理入口组织为“运行概览、订阅、节点、策略、诊断”，服务器接入与凭据放在现有服务器页。手机上用列表与详情页，桌面上用可筛选表格；高级阈值保持折叠，默认只呈现影响当前决策的信息。

概览回答四个问题：当前入口能否服务、还有多少可用容量、近期出现什么异常、管理员下一步该做什么。每次切换记录旧线路、新线路、原因、配置版本和触发指标。节点显示“被排空 / 地区不符 / 容量已满 / 样本过期 / 恢复试探”等实际原因。

增加有限留存的小时 / 天级趋势和事件：成功率、延迟分位数、超时、重连、队列等待、在途占用、切换频率。业务样本、探测样本和客户端样本分别统计；显示窗口与样本数。建议原始样本短期保留、聚合数据长期保留，配置磁盘上限与清理策略，最终默认值根据小 VPS 测试确定。指标写入失败不能阻塞用户请求。

### 用户自己的连接诊断

手机已有 `NetworkDiagnostics`，主要检查模型 API / 图片服务；远程界面已有 `ConnectionIndicator`，可区分连接中、连接中断与电脑离线。已有电脑检查、多站点管理及备用连接恢复也继续复用。后续从连接状态灯进入“连接详情”，保留原服务商诊断，不另建一套状态判定或站点切换机制；用户仍不选择代理节点。

| 测量 | 来源与含义 |
| --- | --- |
| 手机 ↔ Hub | 当前手机经统一入口完成一次受限探测的往返耗时 |
| Hub ↔ 电脑 | 复用现有 `device.ping` 能力，在当前用户已配对设备权限内执行；不向用户暴露管理端接口 |
| 手机 → Hub → 电脑 → Hub → 手机 | 无执行副作用的关联回显，以手机单调时钟计整段耗时；含排队与处理，不解释为纯网络延迟 |
| 模型 / Agent 执行 | 独立显示任务阶段，不归咎为代理 RTT |

不把分段 RTT 相加伪装为完整指令往返，不凭不同时钟时间戳计算单向时延。每次诊断携带短期关联标识，做权限、速率与大小限制，不执行模型任务或任意命令。电脑离线时给出原因和最近观测时间，不能拿旧值当当前延迟。

用户看到“手机连不上入口”“Hub 可达但电脑离线”“正在恢复连接”等可行动提示，以及重新检测、查看说明和导出脱敏诊断摘要。代理地址与订阅仍不可见。自动重连沿用既有回执 / 去重协议，不因 UI 显示重试而重放一次执行请求。

公开 Web 状态页仍用于站点可达性；用户私人设备信息仅在认证后的客户端展示。独立状态站、历史事故与长期可用率按后续运营要求另建。

## D. 有数据以后再自动优化

### 质量选路

先在后台观察候选排序与实际结果，再进行小范围新连接灰度。过滤顺序为启用 / 协议 / 地区限制 / 健康 / 容量，之后再比较成功率、尾部延迟、抖动、重连与排队。设置最小样本量、衰减、切换冷却、最大调权速度和保守回退，不直接把任意加权公式投入生产。

地区、ASN 与运营商数据标注来源和有效期，用户网络分组仅用完成业务所需的聚合信息。距离近不自动优先于实测稳定；多个节点共享供应商带宽时增加组级容量，避免把一个拥塞出口当成多份独立容量。按用户公平限额需要可信业务身份，不接受客户端自报用户 ID 绕过限制。

“手机 / 电脑到入口”与“入口到 Hub”是两个调度层。出口池优化不能解决所有用户到海外入口的慢链路。确有数据证明需要时，再接入多个受控入口，以统一域名和有边界的流量切换改善第一段；DNS 缓存、证书、已建立长连接和 Hub 可用性分别验收。

### 运营与商用放行

开放多人管理前加入角色与服务端逐项鉴权；发布、凭据修改、回滚和授权记录进入持久审计。补全配置备份 / 恢复、密钥轮换与升级回退。告警先在后台聚合，通知渠道由管理员明确配置，采用合并、冷却及恢复通知。

发布必须完成：协议兼容矩阵、指令不重复执行、多用户隔离、容量与慢流测试、至少一轮持续运行观察、升级恢复演练，以及代表性国内宽带 / 移动网络的真实试点。试点前确定并记录预期并发、样本周期和收益门槛，以端到端 p50 / p95、失败率、重连次数与恢复时间判定；不预填“降低多少延迟”。

4. 接入订阅记录、更新差异与定时任务，完成“填一次订阅 → 自动维护”的完整流程。
5. 将新能力放入连续的接入界面，随后交付用户分段诊断与真实趋势。
