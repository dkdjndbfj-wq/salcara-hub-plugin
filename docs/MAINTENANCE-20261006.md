## 与桌面/手机的边界

- Hub 只把手机命令按已配对设备凭证投递给电脑，不保存 API Key，也不决定 A→B 的站点切换；切站事务由桌面 Bridge 验证目标站点，手机核对交接回执。
- 事件缓存有容量上限。超过容量会返回缺口标记，手机必须重新读取电脑上的权威会话；这不是实时永久消息队列。
- command receipt 只允许同一个 request ID 重放同一指令。Hub 重启后没有完整回复的记录按“不确定”处理，绝不自动重复可能已执行的任务。
- 事件批次去重缓存当前保留最近 256 个批次；Hub 重启会清空这段内存缓存，Bridge 仍保留批次号并重试，但若重启恰好发生在回包丢失窗口，手机/电脑仍应以会话权威历史核对，不把 `accepted` 当作永久持久化证明。
- Desktop Bridge 已修正同一 batch ID 的 wire payload 在重试间漂移问题；Hub 不放宽 409 冲突校验。冻结请求也包括缺口提示的时间戳，新事件属于下一批。
