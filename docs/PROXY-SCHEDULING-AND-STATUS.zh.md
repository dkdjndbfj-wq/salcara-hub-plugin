# 代理池调度、检测与用户状态页

本文记录 2026-11-07 的实现契约，以及还需要分阶段建设的商业能力。部署入口、订阅与 SSH 接入见 [服务端入口与线路管理](SERVER-NETWORK.zh.md)。

## 用户与管理员的职责

电脑和手机使用同一个公开 Hub URL，继续原有登记、认证与配对流程，不填写订阅、节点地址、SSH 密码，也不选择节点。节点配置和调度在服务端完成。路径为：

```text
电脑 / 手机 → 公开 HTTPS 入口 → Edge → 可选代理节点 → 固定 Hub
```

管理员必须控制公开入口，或者使用供应商明确提供的转发入口。普通机场的出站订阅不能将原来直达海外 VPS 的用户连接自动搬到机场前面。单独把 VPN 装到原 Hub 上不构成入站加速。公开域名与固定回源域名必须分开，避免回源循环。

## 已实现的调度规则

调度依次检查节点启用状态、排空、健康与样本有效期、地区规则和容量。容量预留与节点选择原子完成，避免并发请求同时看到空位而超限。短请求与 SSE 流连接使用不同预算。

| 模式 | 实际行为 | 使用场景 |
| --- | --- | --- |
| 手动固定 | 固定指定节点；不使用自动地区与未知样本过滤。故障不自动换线，异常或未验证时限为单并发试探 | 排障、明确指定线路 |
| 主备切换 | 优先指定节点，失效时使用符合规则的备用节点 | 希望常用一条主线路 |
| 延迟优选 | 比较固定 Hub 探测的平滑延迟，健康节点之间满足改善门槛及冷却后切换 | 对延迟敏感 |
| 负载均衡 | 在符合规则且有容量的节点间按 `(该类在途数 + 1) / 权重` 选择新请求 | 多用户同时访问 |

“负载均衡”分散不同请求，不将同一条指令复制到多个节点抢响应，不叠加单连接带宽，也不保证精确的流量百分比。前三种模式使用一条当前线路，容量满时按有界队列处理，不因容量满自动切成多节点分流。

### 地区偏好

每个节点可以填写一个地区标签，例如“香港”或“新加坡”。标签由管理员确认，最多 32 个 UTF-8 字节；前后空白规范化，控制与格式控制字符拒绝。地区列表最多 32 项，匹配忽略大小写。地区标签表达运营偏好，不证明 IP 真实位置或用户访问质量。

| 规则 | 行为 |
| --- | --- |
| 不限制 | 所有合格节点参与 |
| 优先这些地区 | 有合格匹配节点时优先使用；负载均衡中匹配节点满载也可回退到其他地区 |
| 仅使用这些地区 | 只允许匹配节点；无合格节点时拒绝新连接，不绕过地区限制 |

地区规则应用于自动模式。未标地区节点不匹配地区列表，可在“不限制”或“优先”的回退阶段参与。直连是显式节点，也受这些规则约束；没有隐藏的直连兜底。禁止直连时应禁用直连节点。

已有可选本地 DB-IP Lite 国家 / ASN 观察，明确显示“服务器地址”来源和有效期；需管理员开启才参与地区选路，人工标签仍优先。尚无按用户 IP 的自适应分组，也不从节点名字中的“香港”“CN2”等词推断线路质量。见 [网络归属说明](NODE-NETWORK-OBSERVATION.zh.md)。

### 延迟与防抖

每次成功测量更新平滑延迟：`新 EWMA = 0.3 × 本次耗时 + 0.7 × 旧 EWMA`。无旧样本或旧样本已经过期时从新样本重新开始。检测耗时覆盖实际建连与读取完整的有界状态响应，不是 ICMP ping。

健康线路之间默认同时满足“改善至少 30 ms”“改善至少 20%”与“上次切换已过 120 秒”才更换。当前线路故障或被地区规则排除时，不等待健康线路之间的改善门槛；当前样本过期时，也不以旧延迟与冷却阻挡切向新鲜候选。主备切换使用主备优先级，不套用延迟优选的冷却。已建立 TCP/SSE 不迁移；切换影响后续新请求。

## 测通与自动检测

检测目标固定为部署配置中的 Hub `/salcara-hub/statusz`，经每个节点的实际传输路径发起独立请求。只有 HTTP 200、响应大小符合限制、JSON 中 `status` 为 `available` 才通过。禁止跳转、超时有界，不把任意网站可达当成 Hub 业务链路可用。

| 操作 | 范围 | 对禁用节点的影响 |
| --- | --- | --- |
| 检测线路 / 定时检测 | 已启用节点，含排空节点 | 不检测禁用节点 |
| 检测全部 | 全池节点 | 只更新诊断结果，不启用、不分配新业务 |
| 节点行“测通” | 指定节点 | 可诊断禁用节点，不改变启用状态 |

新增启用节点、重新启用或变更代理连接配置会安排配置检测；仅修改名称、地区、权重、容量或策略不主动全池测通。策略热更新会调整后续计划，启动时仅在周期检测开启的情况下自动探测。关闭周期检测仍可进行手动与配置检测。一次只执行一轮；同一轮中的重复目标合并，有变化或未覆盖的目标排入后续检测。不会因连续点击产生无界并发。检测进度显示总数、已完成、通过、失败、跳过、是否存在后续检测以及下次计划时间。期间删除、替换节点或更新失败状态后，旧检测结果不得覆盖新状态。

| 参数 | 默认值 | 可配置范围 |
| --- | --- | --- |
| 周期检测 | 开启 | 开 / 关 |
| 每轮完成后的间隔 | 30 秒 | 5–3600 秒 |
| 单节点超时 | 6 秒 | 0.1–30 秒，且不超过间隔 |
| 检测并发 | 4 | 1–16 |
| 连续探测失败后隔离 | 3 次 | 1–10 次 |
| 恢复所需连续成功 | 2 次 | 1–10 次 |
| 恢复最短观察 | 5 秒 | 0–600 秒 |
| 样本有效期 | 120 秒 | 至少为间隔加单节点超时，最多 86400 秒 |
| 延迟优选冷却 | 120 秒 | 0–3600 秒 |
| 最少绝对改善 | 30 ms | 0–60000 ms |
| 最少相对改善 | 20% | 0–100% |
| 允许未知或过期节点试探 | 开启 | 自动模式中开 / 关 |

周期从上一轮结束计算，不是保证每 30 秒全池完成。例如 32 个节点、4 路并发、全部耗尽 6 秒超时，整轮理论量级为 48 秒，再等 30 秒才启动下一轮，另有运行调度开销。节点越多、探测越慢，样本有效期和间隔越需要结合真实情况配置。用户业务并发与此处检测并发完全独立。

### 健康与恢复状态

1. 新节点没有成功实测时为未知。默认允许最多一个在途业务试探，首次成功探测后可使用正常容量；关闭“允许未知或过期节点试探”后，自动模式须等待成功检测。
2. 之前成功的节点一次探测失败显示降级，保留上次成功时间；达到连续失败阈值后自动模式剔除。失败不能把旧成功时间刷新为当前时间。
3. 真实业务连接失败或异常读体中断可立即标记故障；客户端取消单独计数，不误判为代理故障。Hub 返回 HTTP 429/5xx 记入业务失败，不仅凭这些状态剔除所有代理。
4. 故障恢复与重新启用节点先受单并发限制，需连续成功次数及最短观察时间同时达到才恢复正常容量。一次新的失败会清空连续恢复计数和观察起点。
5. 成功样本超过有效期后显示“结果过期”，旧延迟不能当作当前健康成绩。允许试探时最多单并发；禁止时自动模式排除。关闭周期检测不会冻结过期计时。

默认参数不等于固定恢复时限。两次成功之间通常有整轮耗时和间隔，恢复还受网络、并发和排队影响。后台每 5 秒刷新仅读取状态，不启动检测；关闭网页不停止服务端定时检测。

## 容量与链路故障

默认每节点请求 / 流连接上限为 64 / 16；单 Edge 进程为 256 / 128。各可设为 1–4096。队列默认最多 64 项、等待最多 2000 ms；长度可设为 0–4096，等待可设为 1–30000 ms。

| 情况 | 处理 |
| --- | --- |
| 节点满载 | 负载均衡考虑其他合格节点；单线路模式保持当前线路排队 |
| 全局满载 | 有界排队；队列满返回 429 |
| 等待超时 / 无可用线路 | 返回 503；不无限等待 |
| 请求取消 / EOF / 响应体关闭 | 准确释放一次容量，取消及时出队 |
| 节点排空 / 移除 | 不接新请求，仍在途请求自然结束并继续占全局容量 |
| POST 失败 | 不自动重发；客户端按现有命令标识、回执与去重机制恢复 |
| SSE 断开 | 客户端重连，不能将已断连接无损搬迁 |
| 控制面暂时不可用 | 已运行的数据面继续依照其本地配置服务 |
| 入口整机故障 | 配好同一 Hub 的备用 HTTPS 入口后，升级的电脑和手机可在缓存有效期内切换；单入口部署仍无法绕过整机故障 |

这些是准入约束，不是已压测的承载人数。机场可能多个节点共享同一总带宽，入口与 Hub 也可能成为瓶颈。单进程容量不等于多 Edge 的共享配额。

## 用户状态页面

公开页面为 `/salcara-hub/status`，管理页、登录页和使用说明提供入口。它无需管理密钥，只请求最小状态端点；不展示节点 IP、代理凭据、在线设备列表或其他用户信息。

已经实现：

- 区分当前可达、服务返回不可用、异常响应、网络结果不确定、浏览器离线和 8 秒超时。
- 显示本次浏览器请求完整响应的耗时、最近检测时间、最后成功时间；失败尝试不会伪装成成功延迟。
- 默认每次检测结束后 30 秒自动再测；允许手动检测与关闭自动检测，隐藏标签页或离线暂停，恢复可见 / 联网后恢复。
- 最近 12 次实际检测记录仅保存在当前页面内存中，刷新后清空；没有伪造历史可用率。
- 手机窄屏、桌面、明暗主题与手机应用的颜色、品牌、圆角和控件风格对齐。

状态页测量的是“当前浏览器 → 当前公开入口 → Hub”的一次状态请求。它不证明电脑在线、设备已配对、手机指令往返可用或模型响应速度，也不能展示一条不存在的全链路 RTT。新增手机原生连接诊断在已配对设备权限内测量手机↔Hub、Hub↔电脑和完整回显往返；公开页仍不展示私人设备数据。

页面与 Hub 同源；首次访问时入口完全宕机，状态页本身可能无法加载。独立托管状态站、多个外部探测点、事故公告和持久历史需要下一阶段建设。当前浏览器历史不能用来承诺 SLA。

| 自适应并发 | 用真实排队与超时指标在明确最小 / 最大值内调节，设增长速率、冷却和回退；避免机场共享瓶颈引起振荡 | 未实现；已有显式上限、权重和有界队列 |
| 长期监控与权限 | 持久时序指标、配置审计、报警去重、最小权限角色、凭据轮换、备份恢复演练 | 当前为单管理员、24 小时聚合趋势及配置历史；外部告警、RBAC、长期指标平台未实现 |
| 原生连接诊断 | 手机与电脑显示各自到 Hub 的连接状态、最后回执与可解释错误，通过同一 URL 无感工作，不暴露管理员节点配置 | 已有公开状态页和手机分段连接诊断；电脑侧复用受限 device.ping |

推荐先用真实入口做小规模试点：同网络、相近时段对比直连与代理的端到端 p50/p95、失败率、重连次数；故障注入覆盖单节点、全池、入口、Hub、DNS/TLS 和长流。量化目标和回退条件应基于试点确定，不根据订阅节点数量推断收益。

## vm2api 参考

参考 [dofastted/vm2api](https://github.com/dofastted/vm2api) 的代理健康、容量准入和管理信息组织方式，核对提交 `4c9a9392205332d7e8eadb7e22bccef56b19280b`。该版本分配器主要依据健康与绑定容量，地理观察与分配逻辑分开；不能推断其已经完成所有按用户地理位置的自动调度。

本项目按 Hub 请求与 SSE 的生命周期自行实现，没有复制其核心源码。其许可证的商用授权要求与本项目自行实现能力分开处理，详见 [原设计参考说明](NETWORK-ACCELERATION-POOL-PLAN-20261106.zh.md#9-vm2api-参考与多节点并发调度)。
